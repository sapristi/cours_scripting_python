## 4.1 Fil rouge : event-stream, 2018 (5 min)

> [!info] L'histoire en 4 temps
> 1. `event-stream` : petit package utilitaire abandonné, ~1,5 M téléchargements/semaine.
> 2. Un inconnu propose de « reprendre la maintenance » — l'auteur accepte et lui transfère les droits.
> 3. Nouvelle version avec dépendance piégée `flatmap-stream` : code de vol de wallets Bitcoin (cible : Copay).
> 4. Détection plusieurs semaines après : des milliers de projets contaminés via dépendances transitives.

Leçon : le risque n'est pas le code que vous écrivez, mais celui que vous **importez**.
Un `pip install` installe du code + ses dépendances + leurs dépendances — et `setup.py` peut s'exécuter à l'installation.

## 4.2 Panorama des vecteurs en 1 tableau (5 min)

| Vecteur | Mécanisme | Cas réel | Ce qui trahit |
| ------- | --------- | -------- | ------------- |
| Typosquatting | Nom quasi identique au package légitime (`requets` vs `requests`) | Vagues PyPI régulières | Faute de frappe, 0 étoile, auteur inconnu |
| Reprise / transfert | Mainteneur fatigué cède le projet à un inconnu | `event-stream` (npm, 2018) | Changement d'auteur + version soudaine + nouvelle dépendance |
| Dependency confusion | Package interne non publié : l'attaquant publie le même nom en public avec version haute, `pip` prend le public | Clipboard researcher, 2021 (Apple, Microsoft concernées) | Nom interne résolu depuis le registre public, version anormalement haute |
| Backdoor mainteneur | Compromission ou pression sur un mainteneur légitime | `xz-utils` (2024, backdoor SSH avortée de justesse) | Commits suspects, binaires opaques, urgence à mettre à jour |

> [!example] Lecture Blue
> Nom + auteur + date + version = déjà des **IOC** : notez-les avant d'installer, comme une bannière suspecte en module 4.

## 4.3 Les 4 réflexes défensifs (5 min)

1. **Venv jetable, jamais `sudo pip`.** Un package compromis hérite de vos droits — limitez la casse.
2. **Vérifier avant d'installer.** Nom exact, auteur, page PyPI, date et changelog. En cas de doute : ne pas installer.
3. **Pinner + vérifier l'intégrité.** `pip freeze > requirements.txt`, `--require-hashes` en prod, hash SHA256 du sdist (rappel `hashlib` modules 1-2).
4. **Auditer l'existant.** `pip show <pkg>`, `pip audit`, lire `METADATA`. Un audit régulier = **Traçabilité** (AAA, module 1).

```python
import hashlib
from pathlib import Path


def sha256_fichier(chemin: str) -> str:
    """Renvoie le SHA256 hex d'un fichier (ex. sdist téléchargé)."""
    h = hashlib.sha256()
    with open(chemin, "rb") as f:
        for bloc in iter(lambda: f.read(8192), b""):
            h.update(bloc)
    return h.hexdigest()


# Usage : comparer avec le hash publié sur PyPI / dans requirements --require-hashes
print(sha256_fichier("requests-2.31.0.tar.gz"))
```

```python
from importlib.metadata import distributions


def lister_deps() -> list[str]:
    """Liste les distributions installées dans le venv courant (audit lecture seule)."""
    lignes: list[str] = []
    for d in distributions():
        nom: str = d.metadata["Name"] or "?"
        version: str = d.version or "?"
        lignes.append(f"{nom}=={version}")
    return sorted(lignes)


for ligne in lister_deps():
    print(ligne)
```

> [!note] Commandes sûres à retenir
> `pip show`, `pip audit`, `pip freeze` : lecture seule, utilisables sans risque dans votre `venv`.
